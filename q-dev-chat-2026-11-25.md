Clean build. Here's exactly what was wrong and what was fixed:

**Root causes of the Gemini API error:**

**1. Duplicate auth headers (main cause)**
The old code sent the API key in **both** the URL query param (`?key=...`) AND as an `x-goog-api-key` header at the same time. Google's API rejects requests with conflicting/duplicate authentication — it expects only one method. Fixed by removing the `x-goog-api-key` header and keeping only the URL query param, which is the correct method for the Gemini REST API.

**2. Deprecated default model**
`gemini-1.5-flash` and `gemini-1.5-pro` are being deprecated/rate-limited on free tier keys. Changed the default to `gemini-2.0-flash` which is the current recommended free model, with fallback order: `gemini-2.0-flash` → `gemini-1.5-flash` → `gemini-2.0-flash-lite`.

**3. Timeout too short**
The test connection used an 8 second timeout. Gemini cold-start can take longer. Bumped to 10s for test and 20s for actual completions.

**4. `finishReason` handling**
The old code only logged `finishReason` but didn't `continue` to the next model. If Gemini blocked a request with `SAFETY` or `RECITATION`, it would silently return empty content. Now it skips to the next candidate model for any non-`STOP` finish reason.

**To apply:** Reinstall the extension from the rebuilt `dist/` by pressing `F5` in VS Code, or rebuild the VSIX with `python3 package-vsix.py` and reinstall it.
